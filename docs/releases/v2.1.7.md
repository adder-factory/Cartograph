# Cartograph v2.1.7

Cartograph v2.1.7 expands native code intelligence to the textual scripting
languages used across game engines, mods, virtual worlds, and interactive
fiction. It also completes the code-health precision work begun after v2.1.6:
the release candidate is required to index its own checkout with zero error,
warning, and info findings without detector suppression, threshold changes,
severity relabeling, or source exclusions.

## Game scripting coverage

- The stable native registry now contains 126 modes: the frozen 73-mode,
  163-extension v1.1.33 floor; native TOML; and 52 dedicated game-scripting
  modes including Rhai.
- Rhai has a dedicated Unicode-aware bounded tokenizer and structural extractor
  for functions, parameters, variables, literal module imports, exports, and
  calls. Strings and comments are masked and scripts are never executed.
- Fifty-one additional engine, modding, and narrative modes share a bounded
  profile-driven Rust scanner. Each mode proves deterministic symbols and
  references, malformed-input handling, cancellation, and literal safety.
- `.as`, `.c`, `.cs`, `.qc`, `.d`, `.inf`, `.t`, and `.txt` collisions are
  content- or path-qualified. The separate v1 classifier preserves the original
  C/C#/path behavior for historical PostgreSQL imports.
- Module indexing now derives extensions from the typed language registry.
  Same-language relative modules and engine-root paths such as Godot `res://`
  resolve to exact file nodes without making package or cross-language guesses.
- PICO-8 support reads only the textual `__lua__` section. Binary/compiled
  artifacts, visual graphs, generated caches, and cartridge asset sections are
  outside the source boundary.

The exact inventory, research sources, and exclusions are documented in
[Game scripting language coverage](../v2/GAME-SCRIPTING-LANGUAGES.md).

## Code-health precision

- Shared typed inputs replace long parameter lists in extraction, resolver,
  indexing, comparison, and live-test helpers.
- Conditional and secret-handling findings use smaller single-purpose helpers
  while retaining the positive controls for genuinely complex or exposed code.
- CLI error-code mapping is centralized so MCP, auto-sync, and direct command
  paths use the same stable machine-readable result.
- The fixes change implementation structure and evidence production only. The
  release does not weaken a detector, move a threshold, hide a file, or
  downgrade a finding.

## Upgrade notes

Version-to-version upgrades now have one safe, resumable command:

```sh
cartograph upgrade --apply --project-path <PATH>
```

It installs and verifies the release when needed, switches the stable launcher,
applies safe append-only schema migrations, refreshes the generation, runs
`doctor`, proves installed-version freshness from a new process, and repairs
owned MCP pins. Repeating it when the binary is already current heals or resumes
the remaining steps. It never silently replaces a managed database container;
when an older image or HNSW shared-memory boundary requires replacement, it
stops with the exact backup and confirmation commands and resumes after the
same upgrade command is rerun. The report separates running, published, and
installed versions and states explicitly whether the sequence completed and a
host reopen is required because this invocation changed a binary or pin. A
fully idempotent rerun does not request another reopen. Cold managed image pulls
have a separate 15-minute budget and time out into an explicit retry state,
without manufacturing container-incompatibility evidence.

The extractor, resolver, and code-health changes are fenced by migration 29 and
generation digest V10. The upgrade sequence publishes current V10 evidence;
older complete generations remain readable but report stale until that
publication completes.

Cartograph v2.1.7 remains native Rust and PostgreSQL-only. PostgreSQL 18,
ParadeDB `pg_search` 0.25.0, and pgvector 0.8.4 or newer remain external runtime
services. No SQLite runtime, fallback, importer, or dependency was added.

## Verification

The release gate requires the pinned Rust format, Clippy, rustdoc, test, and
dependency-policy suites; deterministic 1/2/4/8/16-worker and live
PostgreSQL/ParadeDB evidence; a zero-finding candidate self-index; Sonar; and an
independent read-only review. Release archives and a signed tag are published
only from the exact reviewed `main` SHA.
