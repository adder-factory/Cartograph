# Cartograph v2.1.17

Cartograph v2.1.17 upgrades the supported PostgreSQL search engine to ParadeDB
`pg_search` 0.25.2. Managed development, CI, and release validation now use the
exact upstream ParadeDB 0.25.2 multi-architecture image digest. External
PostgreSQL deployments likewise require `pg_search` 0.25.2 alongside
PostgreSQL 18.4 or newer within major version 18 and pgvector 0.8.4 or newer.

## ParadeDB 0.25.2 compatibility

- Fresh initialization creates pgvector before `pg_search`, matching the
  extension dependency required by ParadeDB 0.25.2. Existing installations
  update pgvector first and then update `pg_search` in one PostgreSQL
  transaction before any extension-defined function is called.
- Existing generation indexes that use the legacy `bm25` access-method name
  remain queryable after the extension update. New and rebuilt generation
  indexes use the current `paradedb` access-method name, and Cartograph accepts
  both catalog identities at this explicit compatibility boundary.
- Capability checks require the exact supported `pg_search` version, expected
  preload state, ParadeDB access method, BM25 behavior, and `pdb.source_code`
  tokenization. There is no fallback to plain PostgreSQL full-text search.

## Resumable managed upgrade

- The old owned container remains stopped and retained until the replacement
  image passes PostgreSQL health, loopback publication, extension, Cartograph
  migration, and capability proof.
- A failure before extension-catalog mutation safely restores the prior
  container state. Once an extension update has been attempted, the exact new
  image remains the only runnable candidate and the old image stays stopped so
  it cannot load a possibly newer catalog.
- Repeating the same confirmed command resumes a retained candidate and removes
  the old container only after every proof passes. An interruption after the
  old container is stopped and renamed but before the new candidate exists is
  also detected and resumed without manual Docker repair.
- Recovery validates project ownership, the data-volume mount, loopback port,
  container state, image digest, shared memory, and resource ceilings. Foreign,
  running, or otherwise ambiguous rollback topologies fail closed.

## Upgrade

Use the resumable project upgrade:

```sh
cartograph upgrade --apply --project-path <PATH> --json
```

If it reports `requiredConfirmation: upgrade-managed-database`, first create
and retain the private backup command printed by Cartograph, then run only the
reported `cartograph db upgrade` command with the exact
`upgrade-managed-database` confirmation. Repeat `cartograph upgrade --apply`
afterward to finish migrations, indexing, `doctor`, next-process status, and
owned host-registration repair. Require `completed: true`.

Cartograph v2.1.17 remains native Rust and PostgreSQL-only. It does not bundle
PostgreSQL, ParadeDB, pgvector, a database, or a container image, and it has no
SQLite runtime, importer, optional feature, or fallback.
