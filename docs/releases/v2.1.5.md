# Cartograph v2.1.5

Cartograph v2.1.5 is a reliability and precision release. It closes the ten
post-2.1.4 issues in auto-sync, upgrade/registration handling, affected-test
and risk review contracts, and native code-health detector classification.

## Runtime and upgrade reliability

- Auto-sync now retains a stable stage-specific error code, failure time,
  retry time, and attempt count for the failed source revision. Retries use a
  30-second exponential backoff capped at 15 minutes and stop after five
  unchanged failures; a source revision change resets the state.
- Explicit project excludes are applied before nested repository/worktree
  traversal and revision construction, so an ignored private worktree cannot
  be rediscovered or drive a failed-generation loop.
- Versioned installs register the stable
  `~/.cartograph-cli/current/bin/cartograph` launcher. `cartograph upgrade`
  automatically repairs stale Codex, Claude, and Cursor pins through the normal
  safe installer, preserves an existing non-default managed database port, and
  reports each repair outcome.
- A schema-newer-than-binary startup failure now names the running binary,
  database schema version, and supported schema version, exits nonzero, and
  gives explicit upgrade/repin guidance.

## Agent contract fixes

- `cartograph_affected` file mode accepts and enforces the advertised
  `maxNodes` bound and explicit `impact.nodesTruncated` disclosure, matching
  symbol mode and `tests-for` traversal without presenting bounded counts as
  complete.
- `cartograph_review` risk mode is generation-scoped, removes repeated full
  finding scans, bounds each lens, and returns structured `ready`, `timeout`, or
  `unavailable` lens status. Large or non-Git projects can return honest partial
  evidence instead of an unstructured execution failure.

## Detector precision

- `hardcoded_url` distinguishes request destinations and endpoint
  configuration from input hints, navigation/documentation links, validation
  examples, and presentation/vendor asset URLs. Findings expose their category
  and abstention counts.
- `unused_export` requires zero external incoming evidence and excludes
  declaration-only type members. Type-only imports and runtime uses through a
  same-named value/type export retain their external consumer edges.
- `forof_await` abstains for loop-carried awaited dependencies, post-await
  `break`/`return`, and an explicit `cartograph: serial-await` intent marker;
  actionable findings describe the independent-iteration reason.
- `high_fan_out` groups calls, modules, types, composition, and data-flow
  dependencies, and abstains for cohesive returned-object facade factories
  while retaining mixed orchestration findings.
- `duplicate_code` requires privacy-safe identifier compatibility for
  normalized-shape and partial candidates, abstains for cross-domain semantic
  lookalikes, and emits one representative record per complete partial-clone
  component instead of deriving identity from the bounded peer display or
  emitting symmetric member rows. Exact representatives use the same line floor
  as exact-class membership, while semantic representatives and bounded member
  lists use the complete connected similarity component rather than a local
  neighbor minimum.

These contextual detector facts are fenced by migration 27 and generation
digest V8. A normal index after upgrade publishes current V8 evidence.

## Release-note integrity

Release notes are now tracked at `docs/releases/<tag>.md`. The tag workflow
fails closed if the matching detailed file is absent or contains unfinished
markers,
and supplies that file to both draft creation and draft updates. This release
also restores the detailed v2.1.4 notes.

## Verification

The release is built from the exact published `main` SHA after the Rust,
PostgreSQL/ParadeDB, deterministic-worker, Sonar, and independent-review gates.
The four native archives are checksum-verified, smoke-tested, and published
with GitHub build provenance.
