# Cartograph v2.1.13

Cartograph v2.1.13 makes agent auto-sync catch up promptly during rapid editing
while putting explicit ceilings around the background work and managed database
that support it. It removes a redundant source-tree scan from the event path,
bounds continuous-event latency and indexing concurrency, moves routine vacuum
work off the watcher critical path, and reports whether a managed PostgreSQL
container has the supported CPU, memory, and process policy.

## Fresh event-driven auto-sync

An admitted filesystem event now goes directly to the indexer's complete
manifest/no-op fence. The watcher no longer performs a separate full status
manifest scan immediately before asking the indexer to inspect the same tree.
Periodic reconciliation still performs the independent status scan every thirty
seconds, preserving the missed-event correctness boundary.

The default quiet window is reduced to 750 milliseconds and now has a two-second
hard coalescing deadline. Continuous editor or agent writes therefore produce a
bounded stream of reconciliation attempts instead of postponing the next graph
publication indefinitely. An explicit `CARTOGRAPH_WATCH_DEBOUNCE_MS` value above
two seconds remains authoritative and becomes the minimum hard deadline.

Failure handling distinguishes a known source revision from a database outage
that prevents revision recovery. Known revisions retain exponential backoff and
the five-attempt suppression fence until source changes. Unknown-revision
failures share a typed backoff bucket but keep one capped recovery probe, so a
recovered PostgreSQL service cannot leave auto-sync permanently suppressed.
Structured `autoSync` status continues to expose attempts, publications, stable
error codes, failure and retry times, revision-attempt counts, and suppression.

## Bounded background work

Automatic indexing now caps native extraction at four workers and omits the
independent Git churn, co-change, and issue-history enrichment passes. The
structural graph remains complete; an explicit `cartograph index` retains the
normal corpus-aware worker policy and refreshes those auxiliary history
channels.

Automatic generation retention no longer synchronously vacuums every retention
relation after a thresholded cascade. It delegates dead-row reclamation to the
schema's tuned table-specific autovacuum policy. Explicit `cartograph db prune`
keeps the existing thresholded, table-scoped synchronous maintenance report for
operator-audited batches. Neither path performs `VACUUM FULL` or a database-wide
`ANALYZE`.

## Explicit managed-database ceilings

New and confirmed-replacement managed database containers use a 2 GiB hard
memory limit, a 1 GiB reservation, four CPUs, and a 256-process ceiling.
PostgreSQL starts inside that envelope with bounded shared buffers, cache and
maintenance estimates, per-operation memory, connections, and parallel-worker
settings. Its checkpoint interval is 15 minutes with a 4 GiB soft maximum WAL
size and 512 MiB recycled-WAL floor, reducing repeated checkpoint/full-page
write pressure during rapid immutable-generation publication while retaining
`fsync`, full-page writes, and synchronous commit durability. The tradeoff is
bounded extra local disk use and potentially longer crash recovery.

`cartograph db status`, `doctor`, MCP startup preflight, and the resumable
upgrade path inspect and report the observed Docker values. An older owned
container is never silently recreated: adopting the policy uses the existing
backup-gated, explicitly confirmed `cartograph db upgrade` replacement path.
External PostgreSQL remains administrator-owned and is not changed by this
policy.

## Database dependency refresh

The managed image and external capability contract move from ParadeDB
`pg_search` 0.25.0 to the stable 0.25.1 patch. The patch supplies the complete
Docker extension library set and adds vector work-budget, bounds, parallelism,
and training-memory improvements. The managed multi-architecture image remains
digest-pinned, runs PostgreSQL 18.4, and bundles pgvector 0.8.4. The
backup-gated managed replacement updates the extension transactionally and
retains rollback to the previous 0.25.0 container until readiness succeeds.
External PostgreSQL operators can continue using any supported pgvector 0.8.4+
build, with the current 0.8.6 patch recommended for its additional IVFFlat
memory and bounds fixes.

## Upgrade

Use the resumable upgrade path to install the release, reconcile the current
generation, prove database capabilities, and repair owned host pins when
needed:

```sh
cartograph upgrade --apply --project-path <PATH>
```

If the report requests a managed-database upgrade, take the required backup and
run only the exact confirmed replacement command it prints, then repeat the
same upgrade command. Restart or reopen an attached agent host only when the
report says a new process is required.

Cartograph v2.1.13 remains native Rust and PostgreSQL-only. PostgreSQL 18,
ParadeDB `pg_search` 0.25.1, and pgvector 0.8.4 or newer remain external runtime
services. No SQLite runtime, fallback, importer, or dependency is included.
