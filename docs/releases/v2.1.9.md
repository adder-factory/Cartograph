# Cartograph v2.1.9

Cartograph v2.1.9 fixes the two open indexing and review-contract defects in
v2.1.8. Large immediately invoked Rust closures no longer block generation
publication, native pipeline failures retain actionable stage provenance, and
`cartograph_review` now accepts the shared controls published in its schema.

## Rust closure indexing and diagnostics

- Immediately invoked Rust closures are treated as anonymous call targets.
  Their complete expression and body are not emitted as a named `calls`
  reference, while calls inside the closure remain indexed normally.
- Canonical reference-name violations retain the privacy-safe
  `reference_name_too_long` reason. Direct command errors expose
  `reduce/reference_name_too_long`; MCP admin jobs and auto-sync use the stable
  `reduce_reference_name_too_long` code.
- Native parse, resolve, overlay, and reduce failures preserve their actual
  stage instead of being collapsed to `reduce` or generic `operation_failed`.
  A propagated parent pipeline failure takes diagnostic precedence over the
  task-scope poison bit, while dropped, unobserved, panicked, or unreaped child
  work still blocks publication.
- Live regression coverage proves the oversized-closure first publication,
  safe failure with no current generation, safe failure while retaining a
  prior current generation, and absence of source, path, credential, or driver
  text in public diagnostics.

## Review schema alignment

- `cartograph_review` context mode accepts `pathFilter` and `allowStale`, as
  advertised by the public tool schema.
- `pathFilter` now restricts both Git-backed and supplied-diff context evidence
  to a validated project-relative segment prefix. A filter such as `src` does
  not accidentally match `src2`.
- `allowStale` is validated and accepted as a compatibility no-op for Git
  context because the review packet already labels indexed freshness. It
  remains an explicit stale-evidence opt-in for the non-Git lenses.

## Upgrade notes

Migration 30 admits generation digest V11. The extractor contract change makes
an unchanged V10 graph explicitly stale until a normal index publishes V11
evidence. The resumable upgrade path is:

```sh
cartograph upgrade --apply --project-path <PATH>
```

Cartograph v2.1.9 remains native Rust and PostgreSQL-only. PostgreSQL 18,
ParadeDB `pg_search` 0.25.0, and pgvector 0.8.4 or newer remain external runtime
services. No SQLite runtime, fallback, importer, or dependency is included.

## Verification

The release is built from the exact published `main` SHA after the pinned Rust,
PostgreSQL/ParadeDB, deterministic 1/2/4/8/16-worker, Sonar, archive, and
independent-review gates. The four native archives are checksum-verified,
allowlist and privacy audited, smoke-tested, and published with GitHub build
provenance.
