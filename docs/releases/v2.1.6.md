# Cartograph v2.1.6

Cartograph v2.1.6 is a code-health precision release. It closes the eight
synthetic false-positive and missing-consumer cases tracked in issue #114 while
preserving the positive controls for real implementation debt. Ranked findings
and project-wide biomarker statistics continue to share the same detector
policy; no severity, threshold, source-exclusion, or suppression shortcut is
used.

## Executable and structural precision

- Executable-line ownership for TypeScript and TSX now treats static JSX tags,
  attributes, and text as presentation scaffolding while retaining embedded JSX
  expressions as executable syntax. Large imperative functions remain eligible
  for `large_method` and `brain_method` findings.
- `high_fan_out` excludes targets already owned by the source symbol through a
  direct `contains` edge, so nested local helpers do not become architectural
  dependencies. Calls to sibling and external symbols still count.
- `long_parameter_list` reuses the framework-convention classification for
  owned route and entry-point signatures in both persisted and compare/diff
  findings. Ordinary authored five-argument functions remain eligible.

## Content and secret-signal precision

- `sql_string_concat` now requires dynamic text with an ordered statement
  shape: `SELECT ... FROM`, `INSERT ... INTO`, `UPDATE ... SET`, or
  `DELETE ... FROM`. Presentation strings containing an English action verb no
  longer qualify.
- `stale_doc` compares declaration values only when documentation makes an
  explicit numeric claim through cues such as `default`, `limit`, `threshold`,
  or an equivalent assignment phrase. Illustrative numbers abstain.
- `secrets_handling` separates its privacy-safe evidence score from actionable
  exposure. Literal secret material, an environment-secret read, or logging of
  sensitive material can remain actionable; identifiers used only in safe
  cryptographic handling retain evidence without becoming a finding. Exposure
  and environment signals must involve the sensitive identifier within the
  same AST expression boundary.

## Resolution and consumer evidence

- Python built-ins, including standard exception constructors, carry intrinsic
  unresolved provenance, while receiver calls such as `.append()` and
  `.strip()` carry explicit dynamic-dispatch provenance. Genuinely unresolved
  project calls still contribute to `unresolved_reference_pressure`.
- React `lazy(() => import(...))` records a default-export consumer, and
  TypeScript `typeof` queries retain value-consumer edges when resolving the
  corresponding runtime declaration.
- Python's implicit module visibility no longer masquerades as an explicit
  export contract. Python declarations abstain from confident `unused_export`
  findings until explicit export intent can be proven; unconsumed explicit
  TypeScript exports remain eligible.

## Upgrade notes

These extraction, resolver-provenance, consumer-edge, and biomarker facts are
fenced by migration 28 and generation digest V9. After upgrading, run a normal
index so unchanged source publishes current V9 evidence; older complete
generations remain readable but report stale until that publication completes.

Cartograph v2.1.6 remains native Rust and PostgreSQL-only. PostgreSQL 18,
ParadeDB `pg_search`, and pgvector are external runtime services and are not
bundled in the release archives. No SQLite runtime, fallback, importer, or
dependency was added.
