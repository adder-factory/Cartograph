# Cartograph v2.1.15

Cartograph v2.1.15 makes interrupted and resource-constrained indexing
recoverable, adds first-class Slang and WESL code intelligence, reuses semantic
vectors across generations, and tightens several code-health abstention rules.
It also updates the Rust dependency graph and GitHub artifact-attestation action
to their current compatible releases.

## Reliable indexing and observable progress

- Index and sync terminalize every abandoned, unleased staging generation
  before deciding that an unchanged checkout is a no-op. A generation protected
  by a live lease is preserved, and normal retention may collect failed rows.
- A newly published generation is freshness-fenced by one final
  supported-source and index-policy scan. Source that races publication is
  retried twice, then returns the stable `source_changed_during_index` failure
  instead of a successful stale result. An unchanged no-op reuses the exact
  manifest scan that made that decision and does not double its source I/O.
- Unsupported editor metadata such as `.editorconfig` remains outside the
  supported-source revision.
- `cartograph_admin` index-job status exposes live supervisor stage,
  completed-item/byte counters, heartbeat count, idle time, stage timings,
  elapsed time, and cancellation state without exposing source or database
  text.
- Automatic-retention deferral now says whether it is retryable, whether
  `admin unlock` applies, and what to do next. A live `project_busy` outcome is
  explicitly historical and cannot be cleared by stealing the writer's lease.
- Optional enrichment failures distinguish read, write, invalid-data,
  retrieval, and task-execution failures and retain retryability.

These changes resolve #129, #130, and the progress/recovery portion of #132.

## Recoverable deep syntax

Grammar-backed extraction has a project setting, `maxAstDepth`, with a default
of 256 and an admitted range of 64 through 1024. A deeper file is retained as a
partial file with `nesting_limit_exceeded`; extraction reports up to
32 exact normalized degraded paths plus an exact truncated-path count and
continues the rest of the generation. Memory and PostgreSQL spill paths expose
the same report.

This resolves #136 without globally excluding authored `generated/` trees.
Generated/build outputs should still be ignored when they are not source.

## Slang and WESL

The production language registry now contains 130 modes: 64 pinned
grammar-backed modes and 66 bounded custom-scanner modes.

- Slang (`.slang`) uses the pinned Slang grammar and extracts modules, imports,
  interfaces, generics, functions, calls, declared types, and
  `[shader("stage")]` entry points. Dotted module imports resolve to matching
  source paths.
- WESL (`.wesl`) shares the WGSL grammar and adds a bounded WESL import scanner
  for nested collections, aliases, public imports, `package::`, and `super::`
  paths. Modules resolve across `.wesl` and `.wgsl` files.
- Both modes participate in discovery, deterministic identities, module graph,
  search documents, freshness, memory/PostgreSQL generation parity, and the
  live native corpus.

This resolves #134 and #135. The semantic additions are fenced by generation
digest V14 and append-only database migration 38.

## Incremental semantic vectors

Embedding sweeps carry forward matching content-addressed vectors before
endpoint work. The endpoint receives only documents whose rendered embedding
input changed. Reports now distinguish:

- `corpusDocuments`: the complete current-generation document population;
- `reusedDocuments`: matching vectors present before endpoint work;
- `endpointDocuments`: documents submitted during this sweep.

The legacy `documents` field remains the endpoint-work count for compatibility.
Readiness still requires complete generation/model coverage, HNSW, and a query
probe. This resolves #131.

## Code-health precision

- Dynamic SQL detection no longer treats prose containing “select ... from” as
  SQL unless it also has SQL punctuation or a downstream SQL clause.
- Static JavaScript member calls and literal static subscript keys retain
  bounded dynamic-dispatch evidence; computed keys continue to abstain.
- `unused_export` recognizes same-file use rooted in an exported API, ambiguous
  incoming use of any same-named non-private method, configuration-object
  methods, and default-export platform handlers.
- `unresolved_reference_pressure` is explicitly labeled graph-resolution
  coverage, not a compiler diagnostic, and tells callers to verify with the
  language toolchain before editing source.
- Structural status reports `not_computed` instead of synthesizing a perfect
  biomarker score when a generation-fenced detector run is absent.

This resolves #133 and the code-health portion of #130.

## Dependency maintenance

Direct Rust updates include `blake3` 1.8.6, `clap` 4.6.6, `ignore` 0.4.33,
`futures-util` 0.3.34, `globset` 0.4.20, `tree-sitter` 0.26.12, and `thiserror`
2.0.20. The lockfile also advances all compatible transitive packages reported
by Cargo, including the wasm-bindgen family, `rustls-webpki`, `http-body-util`,
`bstr`, `cc`, `find-msvc-tools`, `futures-channel`, `kqueue`, and `whoami`.
The GitHub artifact-attestation action is pinned to v4.2.2.

PostgreSQL 18.4+, ParadeDB `pg_search` 0.25.1, and pgvector 0.8.4+ remain
deliberate runtime compatibility requirements rather than unconstrained Cargo
dependencies. The managed ParadeDB image continues to bundle pgvector 0.8.4;
pgvector 0.8.6 remains recommended for external PostgreSQL.

## Upgrade

Use the resumable upgrade path:

```sh
cartograph upgrade --apply --project-path <PATH> --json
```

Require `completed: true`. Reopen an attached agent host only when the report
sets `restartRequired: true`; an already attached MCP child cannot hot-load the
replacement binary.

Cartograph v2.1.15 remains native Rust and PostgreSQL-only. It has no SQLite
runtime, fallback, importer, or dependency.
