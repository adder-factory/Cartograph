# Cartograph v2.1.14

Cartograph v2.1.14 corrects four reported agent-facing retrieval and
synchronization failures. Content search now scopes paths by the documented
literal-substring contract and reports safe regex parser diagnostics; symbol
batches retain partial results when one input is ambiguous; and
`sync-if-dirty` cooperates with the native event watcher instead of failing on
the watcher's active index lease.

## Reliable content search

For `cartograph_find` with `by: "content"`, `pathFilter` is now a
case-sensitive literal substring of a normalized project-relative path. A
basename, directory segment, or longer path fragment restricts the indexed file
inventory without being silently treated as an anchored prefix. The MCP schema
states explicitly that the value is neither a glob nor a regular expression.

The content `query` remains a bounded, linear-time Rust regular expression.
Invalid syntax now returns an invalid-arguments diagnostic with the fixed parser
category and zero-based byte offset. The diagnostic never includes the supplied
pattern. Expressions that parse but exceed the compiled-size ceiling retain a
separate bounded-size error.

## Partial symbol-batch results

`cartograph_node` no longer aborts a `symbols` batch when one simple name has
multiple exact matches. Resolvable symbols remain in `results`, missing inputs
remain in `unresolved`, and every ambiguous input is named in `ambiguous` with
up to ten candidate symbol IDs, qualified names, kinds, paths, and line spans.
Each ambiguity includes a `truncated` flag so a bounded candidate list is never
presented as complete when more matches exist. Single-symbol resolution keeps
its existing fail-closed ambiguity contract.

## Cooperative explicit synchronization

When `cartograph sync-if-dirty` collides with a native watcher or another index
writer, it now observes the project index lease for a bounded five minutes. It
never steals or deletes the competing lease. Once the writer releases,
`sync-if-dirty` accepts its publication when the live source is current, or
retries its own complete generation when the source remains stale. Normal
storage, publication, and stage failures still propagate with their existing
stable reason codes.

## Upgrade

Use the resumable upgrade path to install the release, reconcile the project,
and repair owned host pins when needed:

```sh
cartograph upgrade --apply --project-path <PATH>
```

Restart or reopen an attached agent host only when the report requires a new
process. An already-attached MCP child cannot hot-load the replacement binary.

Cartograph v2.1.14 remains native Rust and PostgreSQL-only. PostgreSQL 18,
ParadeDB `pg_search` 0.25.1, and pgvector 0.8.4 or newer remain external runtime
services. No SQLite runtime, fallback, importer, or dependency is included.

## Verification

The release is built from the exact published `main` SHA after the pinned Rust,
PostgreSQL/ParadeDB, deterministic 1/2/4/8/16-worker, Sonar, archive, and
independent-review gates. The four native archives are checksum-verified,
allowlist and privacy audited, smoke-tested, and published with GitHub build
provenance.
